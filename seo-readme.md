# CleanCraft Website – SEO Implementation Guide

This document explains **how SEO is handled in the CleanCraft website** and the steps you should follow when adding or modifying pages.

---

## 1. Core SEO Building Blocks

| Feature | Where it lives | What it does |
|---------|----------------|--------------|
| **`src/config/pages.yaml`** | YAML file | Stores per-page marketing metadata (`priority`, `changefreq`, `lastmod`, per-country titles/descriptions, etc.). Consumed at build-time for sitemap generation **and** at run-time by the React app. |
| **`components/EnhancedSEO.tsx`** | React component | Injects canonical URL, **`hreflang`** alternates, robots meta, Open-Graph / Twitter cards, and JSON-LD structured data. |
| **`scripts/sitemap-generator.js`** | Node script | Reads `pages.yaml`, outputs `dist/sitemap.xml` and `robots.txt`. Each `<url>` includes `loc`, `lastmod`, `changefreq`, `priority`. |
| **FAQ JSON-LD** | `components/shared/FAQDisplay.tsx` | When FAQs render, Helmet injects a **FAQPage** schema block into `<head>`. |
| **Robots policy** | Generated by the sitemap script | Disallows admin/dev paths, declares sitemap location. |

---

## 2. International SEO Strategy

1. **Country-scoped paths**: `/in/…`, `/au/…`.
2. **Canonical URL**: Always includes the country code to avoid duplicate-content issues.
3. **`hreflang` tags**: Added automatically for `en-IN`, `en-AU`, plus an `x-default` fallback (`https://cleancraftapp.com`).
4. **Sitemap**: Contains the full country paths so Google can discover every locale.

> **Tip:** If you add a new country, update `EnhancedSEO.generateHreflangUrls()` _and_ `pages.yaml`.

## 4. Updating or Adding Pages

1. **Edit `pages.yaml`**
   * Add a new entry under `seo.pages` with `priority`, `changefreq`, `lastmod`.
   * Provide country-specific `title`, `description`, `keywords`.
2. **Create the React page** and wrap it with `<EnhancedSEO slug="/your-slug" … />`.
3. **Run** `npm run build && npm run generate-sitemap`.
4. **Verify**
   * Open `dist/sitemap.xml` – new URL should exist.
   * Preview the page (`vite preview`) – check canonical, hreflang, and meta tags.
   * Use Google Rich-Results Test for structured data.

---

## 5. Changing the Canonical Domain

The base domain is hard-coded once in `EnhancedSEO.tsx`:
```ts
const baseUrl = "https://cleancraftapp.com";
```
Change this value if the production domain changes, then rebuild.

---

## 6. Testing Checklist

1. **Lighthouse** – run in Chrome DevTools for each major template.
2. **Rich-Results Test** – <https://search.google.com/test/rich-results>.
3. **Robots.txt & Sitemap** – `http(s)://<domain>/robots.txt`, `/sitemap.xml`.
4. **`site:` search** after deployment – ensure only the intended country version is indexed.

## 7. FAQ

### Why do we set `<priority>1.0</priority>` for most pages?
Google treats priority as a _hint_ for crawl order, **not** ranking. By marking all important marketing pages as 1.0 we ensure they are crawled quickly. Technical or low-value pages could be set lower (e.g. 0.5).

### What is `<lastmod>` in the sitemap?
Indicates the last modified date from `pages.yaml` (field `lastmod`). Search engines use it to decide if the page needs re-crawling.
